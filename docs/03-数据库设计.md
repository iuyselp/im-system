## 2. 详细表结构

### 2.1 用户模块

#### im_user (用户表)

```sql
CREATE TABLE `im_user` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '用户 ID',
  `username` varchar(50) NOT NULL COMMENT '用户名',
  `password` varchar(100) NOT NULL COMMENT '密码 (BCrypt 加密)',
  `nickname` varchar(50) DEFAULT NULL COMMENT '昵称',
  `avatar` varchar(255) DEFAULT NULL COMMENT '头像 URL',
  `gender` tinyint(4) DEFAULT 0 COMMENT '性别 0-未知 1-男 2-女',
  `birthday` date DEFAULT NULL COMMENT '生日',
  `phone` varchar(20) DEFAULT NULL COMMENT '手机号',
  `email` varchar(100) DEFAULT NULL COMMENT '邮箱',
  `signature` varchar(200) DEFAULT NULL COMMENT '个性签名',
  `status` tinyint(4) DEFAULT 1 COMMENT '状态 1-正常 0-禁用',
  `online_status` varchar(20) DEFAULT 'offline' COMMENT '在线状态 online/busy/invisible/offline',
  `last_login_time` datetime DEFAULT NULL COMMENT '最后登录时间',
  `last_login_ip` varchar(50) DEFAULT NULL COMMENT '最后登录 IP',
  `created_at` datetime DEFAULT CURRENT_TIMESTAMP,
  `updated_at` datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`),
  UNIQUE KEY `uk_phone` (`phone`),
  UNIQUE KEY `uk_email` (`email`),
  KEY `idx_status` (`status`),
  KEY `idx_created` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户表';
```

#### im_user_token (用户 Token 表)

```sql
  `ip_address` varchar(50) DEFAULT NULL COMMENT 'IP 地址',

  `expires_at` datetime NOT NULL COMMENT '过期时间',

```

## 3. 索引设计

### 3.1 索引原则

1. 主键使用自增 ID 或雪花算法 ID
2. 唯一约束字段建立唯一索引
3. 查询条件字段建立普通索引
4. 时间范围查询字段建立索引
5. 避免过度索引（单表不超过 5 个）

### 3.2 关键索引

| 表 | 字段 | 索引类型 | 说明 |
|----|------|----------|------|
| im_user | username | UNIQUE | 登录查询 |
| im_user | phone | UNIQUE | 手机登录 |
| im_friend | (user_id, friend_id) | UNIQUE | 好友关系查询 |
| im_group_member | (group_id, user_id) | UNIQUE | 成员关系查询 |
| im_message_* | msg_id | UNIQUE | 消息去重 |
| im_message_* | (to_id, created_at) | INDEX | 消息列表查询 |
| im_conversation | (user_id, target_id) | UNIQUE | 会话查询 |
| im_ticket | ticket_no | UNIQUE | 工单查询 |

## 4. 分表策略

### 4.1 消息表分表

```java
// 分表路由策略
public class MessageTableRouter {
    
    private static final int TABLE_COUNT = 100;
    
    // 根据用户 ID 计算表后缀
    public static String getTableSuffix(Long userId) {
        return String.format("%02d", userId % TABLE_COUNT);
    }
    
    // 获取表名
    public static String getTableName(Long userId) {
        return "im_message_" + getTableSuffix(userId);
    }
}
```

### 4.2 分表规则

- 分表键：用户 ID（发送者或接收者）
- 分表数：100 张表（im_message_00 ~ im_message_99）
- 路由算法：user_id % 100
- 查询策略：单聊查 2 张表，群聊查 1 张表

## 5. Redis 缓存设计

### 5.1 Key 设计规范

```
# 用户相关
user:info:{userId}                    # 用户信息
user:token:{userId}:{deviceId}        # 用户 Token
user:online:{userId}                  # 在线状态
user:session:{sessionId}              # WebSocket 会话

# 消息相关
msg:unread:{userId}                   # 未读消息数
msg:offline:{userId}                  # 离线消息队列
msg:sequence:{conversationId}         # 消息序列号

# 群组相关
group:info:{groupId}                  # 群信息
group:members:{groupId}               # 群成员列表
group:muted:{groupId}                 # 群禁言状态

# 客服相关
ticket:agent:{agentId}                # 客服工单
ticket:queue:{groupId}                # 工单队列
agent:status:{agentId}                # 客服状态

# 通用
lock:{resource}                       # 分布式锁
cache:{module}:{key}                  # 通用缓存
```

### 5.2 缓存过期策略

| Key 类型 | 过期时间 | 说明 |
|----------|----------|------|
| user:info | 30 分钟 | 用户信息 |
| user:token | 7 天 | 登录 Token |
| msg:unread | 永久 | 未读数（实时更新） |
| msg:offline | 7 天 | 离线消息 |
| group:info | 1 小时 | 群信息 |
